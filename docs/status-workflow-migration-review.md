# Status Workflow: Database Review Proposal

**This is a design proposal only. Do not execute it against Supabase until Person B approves the schema, roles, and RLS policies.**

## Current limitation

`public."MOVA"` has a single `status` field, but no immutable status trail, assignment/fix timestamps, or measurement history. A client-only check cannot stop a direct database update from skipping workflow stages.

## Minimum contract

- Keep `public."MOVA".status` as the current status: `reported`, `assigned`, `fixed`, or `verified`.
- Add `public.mova_issue_measurements` with `issue_id`, `measurement_type`, `recorded_at`, `recorded_by`, measurement values, evidence URL, and `confirms_fixed`.
- Add `public.mova_issue_status_events` with `issue_id`, `from_status`, `to_status`, `changed_at`, `changed_by`, and an optional `verification_measurement_id`.
- Route transitions through one transactional RPC/function. It must permit only `reported → assigned → fixed → verified`, and permit `verified` only when a distinct `measurement_type = 'verification'` record is later than the `fixed` event and has `confirms_fixed = true`.
- Do not allow direct client updates to `MOVA.status`; align RLS with approved staff roles and the RPC. New tables should have RLS enabled before any access policies are approved.

## Draft DDL for review

```sql
-- Review only. Do not execute without Person B's approval.
create table public.mova_issue_measurements (
  id bigint generated by default as identity primary key,
  issue_id bigint not null references public."MOVA"(id) on delete restrict,
  measurement_type text not null check (measurement_type in ('verification')),
  recorded_at timestamptz not null default now(),
  recorded_by uuid not null references auth.users(id),
  slope_deg numeric,
  evidence_url text,
  confirms_fixed boolean not null default false
);

alter table public.mova_issue_measurements enable row level security;

create table public.mova_issue_status_events (
  id bigint generated by default as identity primary key,
  issue_id bigint not null references public."MOVA"(id) on delete restrict,
  from_status text,
  to_status text not null check (to_status in ('reported', 'assigned', 'fixed', 'verified')),
  changed_at timestamptz not null default now(),
  changed_by uuid not null references auth.users(id),
  verification_measurement_id bigint references public.mova_issue_measurements(id),
  check (
    (to_status = 'verified' and verification_measurement_id is not null)
    or (to_status <> 'verified' and verification_measurement_id is null)
  )
);

alter table public.mova_issue_status_events enable row level security;
```

The tables alone do not enforce transition order. Person B must approve a transaction-safe transition function and the roles permitted to call it; its RLS policies must be designed before deployment and must not grant broad direct updates.
